# WhatChord Website

The WhatChord website is generated by Astro and deployed as static assets with a
small Cloudflare Worker. Astro owns shared layouts, metadata, article
collections, indexes, related links, and the sitemap. The Worker handles dynamic
social-preview metadata for shared `/try` links.

## Development

The repository uses [mise](https://mise.jdx.dev/) to pin Node.js 22. npm is
included with Node.js; it is not installed as a separate mise tool.

From the repository root, install the pinned tools and the locked JavaScript
dependencies:

```console
mise install
mise exec -- npm ci
```

Start the Astro development server with:

```console
mise exec -- npm run site:dev
```

Build and type-check the static site with:

```console
mise run site:check
mise run site:build
```

The production-like local server includes the custom Worker:

```console
mise run site:build
mise exec -- npx wrangler dev --config docs/site/wrangler.toml
```

## Content

- `src/content/articles/` contains article metadata and bodies.
- `src/layouts/` and `src/components/` contain shared page structure.
- `src/pages/` defines the public routes.
- `public/` contains files copied unchanged into the build.
- `dist/` is generated and is not committed.

Article filenames are public identifiers. Keep the existing `.html` routes
stable when renaming or adding content, and add redirects for intentional moves.

## Chord Engine

`public/js/chord-id.js` is a committed generated artifact because it is loaded
by both the browser demo and the Cloudflare Worker. Regenerate it after changing
the theory engine or `tool/web/chord_id_main.dart`:

```console
mise run site:engine
```

Verify that the committed bundle is current without modifying it:

```console
mise run site:engine:check
```

`mise run site:build` runs this verification before building the site.
